# 品质与验收

## 写清好的标准

- 功能、体验、美术和手感同时定义：玩家在什么场景做什么、得到什么反馈；风格、轮廓、材质、空间、UI、动作和声音只选相关维度。参照绑定具体图或时段、学习维度和允许差距，不只写“AAA”“精美”。
- 每项写“做什么／什么程度算好／用什么证明”。证据可以是实机观察、测试结果或必要媒体，不要求每项生成文件。
- 大任务先做代表样件校准再扩展；美术与布局同期推进，不留到最后。默认不设中途白盒检查点，确有必要才说明理由并请用户确认；功能扩展与品质提高可分阶段。保留整体构图、视线、空间和共享状态，模块通过后仍需组合验证。
- 保留可恢复基线。用户已认可的表现是回归红线；未被要求的不改，主动改动已认可表现须先说明理由并同条件 A/B 证明更好；普通关联回归至少不差。退步先修复或撤回，不降门槛换通过。

## 通过与未通过

品质类目标以实际画面与体验为核心，功能检查只是前提：

1. 同一候选版本实际跑过相关流程，在正常游玩距离、视角、运动和并发状态下检查。静态项对照固定机位，时序和手感看连续过程，Goal 指定必要录像项；不能用近景、暂停帧或不同版本的通过记录替代。
2. 与参照和有效基线并排，写实际差距；列出本项目的廉价感清单并清零，例如平涂特效、大片死黑、无层次材质、动作拖沓。在项目资产约束允许时优先成品资产；素材不足如实列缺口，不用占位凑数。
3. 关键品质改动由新上下文的只读评审检查，只给目标、通过线、参照和证据，不给代码、制作说明或自评。评审明确判达标或未达标，回答哪里廉价、哪里不如上一版，不只给分。先抓阻断和一至两个最大差距，制作方核实原因再改；小修复局部回归。L0 由用户评审。来源可识别的 A/B 不称盲测。
4. 评分、自动检查和投入时间都不能证明体验成立。空间、卡住、输入响应、难度、性能等配实际指标；bot 多局统计只是下限，声音、手感和难度仍需用户实听试玩。不能降低测试负载制造改善，或为提分削弱已认可表现、堆密内容；指标与玩家体验冲突时，以用户反馈为准修订指标，不擅自放宽品质门槛。工具成功也不能覆盖关键警告。
5. 全范围达到约定标准才完成。“待你确认”只用于事先列出的主观项，且 AI 侧检查和适用的独立评审均通过；可以按约定结束持续执行，但不等于验收通过。AI 侧不达标写“未通过”，缺检查写“没跑”，不写“基本通过”。画面项未通过不得判完成。

每项完成要有：已保存版本、实机结论、相关回归、参照对比（适用时）、剩余差距。基线可复用；既无有效证据也不能重建时如实写没跑。主观舒适项以用户已确认版本为准，竞品数字仅作参考，冲突时询问用户。回归红线不适用停滞豁免。

## 证据与留存

- **先确定问题再取证**：编号场景绑定输入、机位、参照和通过条件，固定非目标变量。核实工具没有改变游戏状态；取证超时或未到目标状态不算通过。普通迭代以实机检查、测试和简短结果为主，相关版本和条件未变时复用证据。
- **减少重复图片**：调参只拍回答当前问题的必要机位，不每次重拍全部机位、涂装或验收项。完整覆盖集中在稳定候选与必要交付节点；公共材质、光照变化仍检查受影响的回归范围。给用户默认呈现 1–2 张重点对照板，完整机位备查；不为凑机位把细节缩成无法判断的缩略图，也不因默认数量漏必要证据。
- **每轮及时淘汰**：新证据验证有效后、下一轮尝试前，清理已授权范围内被替代的调参图、重复渲染、裁切、拼板和转换副本，不拖到任务收尾。保留有效基线、当前候选、必要对照及未解决问题的最小失败样本；final1/final2 等命名和日志提及都不是长期保留理由。当前待验收或仍支撑有效结论的唯一证据不删。
- **媒体只留必要一套**：同一证据支持多个验收项。诊断短片通常 30–60 秒，不录等待和重复尝试；必要完整流程只留一份未剪接原片，另留它无法清楚覆盖的证据。沿用项目留档位置，无约定用 dev-history/；场景图优先 JPEG，精细 UI 可用 PNG，同图不保留无用途的多格式副本。
- **容量与授权**：Goal 明确专属临时目录、清理范围与时机。范围已授权则不逐份问；项目仍要求逐次确认时先列清单取得授权，不绕过约定，也不继续无必要地堆图。500 MB 是普通临时媒体的兜底整理线，达到时先整理再批量取证，未达到也按每轮规则清理。完整原片单列，不因体积截断或删除唯一必要证据。用户原件、源工程、正式资源和范围外档案受保护。
- **收尾**：更新必要引用与失效说明，在现有结果中简报保留量和释放量，不新增清理报告。独立评审复用同一有效证据包，不各自重复采集。

用上一轮失败自查，没有历史时按相关品质线检查。写完 Goal 后检查：是否只有任务没有标准，是否把功能通过当品质通过，是否用重复取证代替判断，是否只约定最终清理。只补实际缺口，不生成固定反查表。
