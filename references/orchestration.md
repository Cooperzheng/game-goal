# 编排档位与授权

决定本次执行能派多少独立工作者、用哪种编排，并写成用户可确认的条款。这里只写能力；能力在各宿主叫什么、怎么用、有什么坑，见对应的宿主附录。

## 档位

| 档位 | 允许的编排 | 需要的能力 | 宿主没有这项能力时 |
|---|---|---|---|
| L0 | 只有主会话，不派任何子代理（包括检索类） | 无 | — |
| L1 | 加子代理：只读评审、调研、文件不重叠的独立模块 | 能派出看不到主会话历史的工作者并收回结果 | 改用“评审包”：把目标、通过线、参照、证据路径和要回答的问题整理成一段，交新开的会话或用户评审 |
| L2 | 加限定场景的脚本化编排 | 由运行时按脚本执行的编排（并行、流水线、汇总） | 降到 L1：主会话按 Goal 里的固定清单逐个派评审，每轮在进度里勾选执行情况；规程一致性靠清单，耗时更长 |
| L3 | 加会话级自主编排 | 宿主的会话级自主编排开关 | 降到 L2；没有 L2 再降到 L1 |

- 只读与隔离：宿主能强制就强制；不能强制就写进指令，并在汇报里附核对结果（如版本库状态没有改动）。没有隔离副本时，并行只允许文件完全不重叠，否则改为顺序做。
- 能力取决于宿主，执行质量取决于模型：同一宿主换成较弱或上下文较小的模型，可降一档，把清单写细。

## 推荐规则

- **L0**：全部是客观可验证的小改动，改动集中；主观项由用户试玩、试听判断。
- **L1（默认）**：有主观项需要独立评审；需要调研；或有边界清楚、文件不重叠的独立模块可以并行。反馈批量修改、单次独立评审通常停在 L1。
- **L2**：满足任一项：两个以上对象的多轮对标盲比；每个对象需要多人评审投票，或评审结论要先经测量反驳再交制作方（对抗验证）；跨大量来源的调研，或大批量检查（截图、资产、场景、回归）；较多大型并行模块。
- **L3**：只在调研、审计、终验这类阶段提出，写明代价：每个实质任务都会大规模编排，消耗与耗时明显增加。不用于实现阶段的耦合美术迭代。
- 推荐写一句理由，复杂方案才比较相邻档位的取舍。宿主能力不足时写：“推荐 Lx；本宿主最高 Ly；实际 Lz；损失：……；补偿：……”。

默认上限（用户可改，已确认的值沿用）：子代理同时不超过 3 个；每次脚本化编排不超过 5 个代理；评审团 3 人；每轮最多 1 次评审团。

## 确认块里怎么写

确认块用一两句话概括宿主、档位、启用机制的用途、上限、预计用量和留存；未用机制合并写“其余不用”。详细条款只在 Goal 正文写一次。回复“确认 [Lx]”生效；只回“确认”按不高于推荐的 L0／L1 执行，L2、L3 必须写出档位。

预计用量按“每轮派几个、预计几轮”估算，不作为停止条件；注明宿主的模型与推理强度对消耗的影响（各附录写了怎么查）。

## 禁区

所有档位都适用，除非用户明确放开：耦合的画面系统（光照、材质、后处理、特效、场景美术）和共享核心文件，只由主会话一人按顺序修改。子代理与编排只用于评审、调研、批量检查和文件不重叠的模块。

## 授权条款

只写本次适用的条款，已有约定简写摘要；独立执行的 Goal 保留完整适用约定。

1. **来源**：授权出自用户自己发出的消息——确认回复（L2、L3 须写出档位）或启动命令；Goal 文档记录完整条款，供每轮重读，也能扛住上下文压缩。AI 起草的条款在用户确认前不算授权。
2. **机制**：子代理、脚本化编排、会话级自主编排分开授权。档位低于 L3 时，开工前先确认宿主没有处于会话级自主编排；如已开启，请用户先关闭再执行。
3. **决策权**：档位是上限，条款写明用在哪；条款范围内由执行方判断，不逐次询问；另写禁区。
4. **用量与预算**：写明并发、单次编排规模与每轮次数上限，非评审用途另列本段总量。独立评审（含盲审）默认不设累计人次、编排总次数和单项轮数上限，按已确认整体预算与局部停滞条件推进；有可验证改善则继续，达标即止。用户明确指定评审硬额度时才设，并预留终验用量。每轮报累计用量；显式额度耗尽只停受限活动，继续其他独立工作并询问是否追加。轮次与工时按停止条件计入整体预算。
5. **角色权限**：评审只读，只看目标、通过线、参照和证据，不看代码、制作说明和自评；模块代理只改列明的文件；任何代理不推送、不发布、不装全局工具、不删除主工作区文件；合并由主会话负责。并行前先写契约：接口、文件归属、共享参数、构图预留位。
   - 是否开隔离副本按任务临时判断（项目有约定按约定）：需要各自构建、截图或长时间独立跑的才开；文件不重叠、验证可以由主会话合并后统一做的，就在同一分支上做。判断和理由写进条款；执行中临时要开（如重拍基线做 A/B）就在进度里记一行。开了的副本收尾删除。
   - 同一分支并行时：子代理不提交，由主会话提交；构建、截图和试玩由主会话在合并后统一跑。
6. **共享资源**：占用 GPU 的性能测量与基线截图串行跑，不与其他代理同时进行；帧时间只认 GPU 空闲时的测量。
7. **失败处理**：代理长时间没有进展先停掉，再重开或由主会话接手；失败也计一轮。
8. **汇报与有效期**：每次编排结束写一行（用途／代理数／结论／累计用量），同步进度页；授权在本 Goal 内有效，换 Goal 或改范围、额度时重新确认，范围不变不重复确认。
9. **留存**：写明节点图位置、本轮专属临时目录与清理范围、录像项；随 Goal 一并确认，范围内已替代的中间产物及时清理。留存按品质线的“证据与留档”，项目另有约定时从其约定。

## 升降档

- 降档：执行方可以自行决定，在进度里记一行原因。
- 升档、追加额度，或超出条款写明的用途、规模、禁区：先问用户，用户写明新档位或新额度后执行。

## 条款模板

方括号是待填项，数字沿用已确认的值。

```
## 编排授权（用户 [日期] 回复“确认 [Lx]”，本 Goal 内有效）
- 档位：[Lx]。理由：[一句话；复杂方案再说明档位取舍]。
- 子代理：用于 [评审／调研／列明的模块]，何时派出由你判断；同时 ≤[3] 个；非评审用途本段最多 [N] 人次。
- 脚本化编排：[不用]／只用于 [评审团／调研／批量检查／列明的并行模块]；每次 ≤[5] 个代理、每轮 ≤[1] 次；非评审用途本段最多 [N] 次；这些场景内是否启用由你判断。
- 会话级自主编排：不开；开工前确认宿主未开启，已开启时先请用户关闭，关闭前以本节为准。[L3：仅 [阶段]；代价 [……]；阶段结束即关。]
- 禁区：[光照、材质、后处理、特效、场景美术] 由主会话一人按顺序修改。
- 权限：评审只读；模块代理只改 [文件]，[同一分支／隔离副本：理由；收尾删除]；不推送、不发布、不装全局工具；合并与清理由主会话做。
- 资源：[GPU 测量与基线截图] 串行。
- 留存：节点图放 [位置]，临时产物放 [本轮专属目录]；只留当前有效证据、必要对照和关键失败样本，范围内已替代产物及时清理，简报数量与体积；待验收、仍引用或未解决问题所需的证据不删，原件与历史档案不动。录像 [不录／只录 [项] 的必要片段]，有效证据复用，不逐轮留副本。
- 预算与汇报：独立评审按整体预算与局部停滞条件推进，不另设累计人次、编排总次数或单项轮数上限（用户明确指定硬额度时另写）；显式额度耗尽只停受限活动，继续独立工作并问我；每次编排结束报累计用量。
- 执行宿主：[宿主]，按其附录对应。
```
