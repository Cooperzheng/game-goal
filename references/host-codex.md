# 执行宿主：Codex

核实于 2026-10（Codex CLI 0.131）。宿主升级后，先按文末“复查项”核对再用。本文只写对应关系和坑，通用规则见 [编排档位与授权](orchestration.md)。

## 档位对应

- **L0 → 不派子代理。**
- **L1 → 子代理（默认开启）。** 只在用户直接要求，或项目、skill 指令要求时才派，不会自行派出：Goal 写明用途、并发上限和是否等结果；独立评审按整体预算与局部停滞条件安排，其他用途遵守约定额度。
  - 只读只能写进指令：官方说明自定义代理不会得到单独的只读沙箱，权限与沙箱继承主会话。评审结束后附版本库状态，核对没有改动。
  - 子代理继承当前沙箱，没有逐个的隔离副本：要并行改代码，文件必须完全不重叠；需要各自构建、截图的支线改为顺序做，或由用户另开对话、各用一个 worktree（Goal 里写明理由，收尾删除）。
  - 并发上限可用 `agents.max_concurrent_threads_per_session` 配置；主会话会等所请求的结果全部到齐再合并。
  - 估算用量时看主会话与子代理的模型和推理强度：配置里的 `model_reasoning_effort`、`[agents]` 默认值或自定义代理文件；子代理没有单独设置时继承主会话。
- **L2 → 无原生对应。** 降到 L1，按编排档位里的补偿写法：主会话按固定清单逐个派评审。
- **L3 → 无对应。** 降到 L1。

授权方式：回复“确认 L1”（或“确认 L0”）。推荐 L2、L3 的 Goal 在本宿主写成“实际 L1”，并写明损失与补偿。

## 启动与判定

- 短任务：用户回复确认后直接执行。长任务：确认后写入 Goal 文档，再用 `/goal` 启动。
- `/goal`（Goal 模式，核实时为实验功能）：目标文本同时是第一条提示和完成标准，由执行任务的代理自己判断是否完成；文档没有写内置的轮数或时长上限。所以：
  - 品质类目标的目标文本写明画面验收条件和“画面项未通过不得判完成”；主观项必须过独立评审并经用户确认才算完成。
  - 停止条件写进目标文本和 Goal 文档，每轮在状态块里自报时间戳和累计用量。
- 启动命令示例：`/goal 完成[……]，唯一依据是[Goal 文档]。编排按「编排授权」一节：按其中逐项派子代理（[用途]），其余不用。画面项未通过不得判完成。`
- 没有 `/goal` 时，把同样内容作为提示直接发送；目标还不清楚时先用 `/plan` 澄清。

## 安装与调用

- 用户目录 `~/.agents/skills/game-goal/`，仓库目录 `.agents/skills/game-goal/`；部分版本也读取 `$CODEX_HOME/skills/`。
- 默认按描述自动触发，也可用 `$game-goal` 或 `/skills` 显式调用。想只在点名时用：把 `agents/openai.yaml` 的 `policy.allow_implicit_invocation` 改为 `false`。

## 复查项

子代理的触发方式、只读与隔离；是否出现原生的脚本化编排；`/goal` 的判定方式与上限；skill 目录。
